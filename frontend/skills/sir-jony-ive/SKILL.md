# Criterio de diseño bajo demanda

Localiza el cerebro en este orden: una ruta indicada por el usuario, `SIR_JONY_IVE_ROOT`, `docs/brain/` del proyecto o el checkout personal si existe. Comprueba `AGENTS.md` y `core/suelo.md`; no dependas de una ruta absoluta de otra máquina.

Lee `AGENTS.md`, el suelo y el playbook o mapa de la decisión. Abre solo las notas referidas que necesites, normalmente no más de ocho; `sources/` sirve para comprobar citas. No cargues el cerebro entero.

El contrato del producto resuelve identidad, stack y tokens. Un ADR del cerebro con estado proposed es una propuesta. Si dos criterios chocan, explica el conflicto y resuélvelo según el encargo y la evidencia del producto.

Devuelve una decisión aplicable con su motivo y las notas consultadas. Si no existe un checkout accesible, indica esa limitación y usa el contrato local; no atribuyas al cerebro reglas que no has leído. La fuente es https://github.com/jesus-guti/sir_jony_ive ; este perfil instala el acceso, no copia el segundo cerebro.

Cuando el usuario dé feedback visual, utiliza el playbook de capturar gusto si ese trabajo forma parte del encargo. Una preferencia de un producto no se convierte automáticamente en una regla universal.
